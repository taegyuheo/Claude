# 2분할 인터랙티브 코드 분석 HTML — 작성 방침

`upload/` 의 C 소스 하나를 **왼쪽 코드 / 오른쪽 분석 카드** 구조의 HTML 한 장으로 만드는 방법을 정리한 문서다.
**기준 예시는 `tools/example/example.c` + `tools/data/example.js`** 이고, 빌드하면 `result/example.html` 이 된다
(`bash tools/build.sh tools/example/example.c`). 새 파일을 분석할 때 이 문서 순서대로 하면 된다.

> 결과물 규칙의 요약은 `CLAUDE.md` 에 있고, 이 문서는 **만드는 절차와 데이터 형식**을 자세히 다룬다. 두 문서가 다르면 CLAUDE.md 가 우선이다.

---

## 1. 구성 파일

```
tools/
├── 작성방침.md            이 문서
├── viewer_template.html   공통 엔진 (화면 구조, 구문 강조, 카드 그리기, 이벤트)
├── build.sh               합치기 + 검증 한 번에
├── example/
│   └── example.c          기준 예시 원본 (Linux 표준 C, 외부 라이브러리 없음)
└── data/
    ├── example.js         기준 예시 데이터 — 새 파일은 이것을 복사해서 시작
    └── <이름>.js          실제 분석 대상의 데이터
upload/
└── <파일>.c               분석 대상 원본 (upload/src/ 아래에 있어도 됨)
result/
└── <이름>.html            결과물 (build.sh 가 만든다 — 직접 고치지 않는다)
```

`example.c` 에는 결과물에 나올 요소가 모두 들어 있다: 매크로, 전역 플래그와 신호 핸들러, 파라미터와 리턴값이 있는 직접 만든 함수, 메인 루프와 지연, `goto cleanup`, 여러 실패 경로.
데이터를 쓸 때 막히면 `example.js` 에서 같은 종류의 심볼을 찾아 형식을 따른다.

| 바꾸고 싶은 것 | 고칠 파일 |
|---|---|
| 특정 파일의 설명 문구, 카드 내용, 실행 흐름 | `tools/data/<이름>.js` |
| 모든 결과물에 공통인 화면 구조, 카드 틀, 색, 동작 | `tools/viewer_template.html` → **모든 결과물을 다시 빌드** |

`result/*.html` 을 직접 고치면 다음 빌드 때 사라진다.

## 2. 작업 순서 (새 파일 하나)

```bash
# ① 데이터 파일 만들기 — 기존 것을 복사해 시작
cp tools/data/example.js tools/data/02_traffic.js

# ② 소스를 읽고 데이터 채우기 (3장 형식, 4장 내용 기준)

# ③ 빌드 + 검증
bash tools/build.sh 02_traffic.c
```

`build.sh` 가 하는 일:

| 단계 | 내용 | 실패 시 |
|---|---|---|
| 합치기 | 템플릿의 `@@SOURCE@@` ← 원본 그대로, `@@DATA@@` ← 데이터, `@@FILE@@` ← 파일 이름 | — |
| 원본 일치 | 코드 뷰어에 들어간 소스와 원본을 diff (CRLF/LF 차이는 무시) | 중단 |
| 실행 | Chrome/Edge 헤드리스로 열어 스크립트 오류(`Uncaught`)를 확인하고, 줄 수·심볼 수·개요 표시를 센다 | 중단 |
| 빠진 카드 | 코드의 함수 호출 중 카드가 없는 것을 나열 (`△ 카드가 없는 함수: ...`) | 경고만 |
| 스크린샷 | 개요 화면을 임시 폴더에 저장 | — |

④ 스크린샷과, 대표 함수 카드 2~3개(`result/<이름>.html#심볼키`)를 눈으로 확인한다.

> 이름 규칙: `example.c` → `example`, `util.h` → `util_h` (데이터 파일과 결과물 이름이 같다)

## 3. 데이터 파일 형식 (`tools/data/<이름>.js`)

반드시 정의할 것: `META`, `OVERVIEW`, `SECTIONS`, `REGS`, `SYM`, `ALIAS`.
엔진이 미리 정의해 두는 것: `ROLES`, `hex()`, `esc()` (데이터 안에서 써도 된다).

### 3-1. META, OVERVIEW

```js
const META = { subtitle:'라이브러리 · 보드 · 한 줄 설명' };   // 상단 바에 표시

const OVERVIEW = {
  heading:'이 코드가 하는 일 (한 문장)',
  summary:'2~3문장 요약. 배선, 종료 방법, 이 예제에서 배우는 점',
  sim: {                        // 루프를 보여 줄 게 없으면  sim: null
    title:'메인 루프 시뮬레이션', intro:'재생 전 안내 문구',
    from:53, to:57, ms:500,     // 강조할 줄 범위, 주기(ms)
    on:'켜질 때 문구', off:'꺼질 때 문구', stop:'정지했을 때 문구',
  },
};
```

### 3-2. SECTIONS — 줄 범위별 역할 (코드 왼쪽 색 띠 + 개요의 실행 흐름)

```js
const SECTIONS = [
  { from:23, to:27, role:'signal', title:'Ctrl+C 준비', desc:'SIGINT → on_sigint 연결' },
  { from:58, to:58, role:'loop',   title:'', desc:'' },   // title 이 빈 칸이면 색 띠만, 개요 목록에는 안 나옴
];
```
- `role`: `global`(전역 정의) · `signal`(신호 준비) · `init`(초기화) · `loop`(메인 루프) · `delay`(지연) · `shutdown`(종료) · `cleanup`(정리)
- 줄 번호는 **원본 번호**다. 주석 줄을 범위에 포함해도 된다 (화면에서는 숨겨지고, 링크는 아래쪽 가장 가까운 줄로 이동한다).

### 3-3. SYM — 심볼 사전 (카드 내용)

키는 코드에 나오는 이름 그대로 쓴다. 코드의 이름과 키가 같으면 자동으로 클릭 가능한 요소가 된다.

**공통 필드**

| 필드 | 필수 | 설명 |
|---|---|---|
| `kind` | ✓ | `func` · `var` · `macro` · `const` · `kw` · `op` · `reg` |
| `role` | ✓ | SECTIONS 와 같은 역할 키 |
| `sig` | ✓ | 원형 / 선언 / `#define` 줄 (그대로 표시, HTML 아님) |
| `summary` | ✓ | 한 줄 요약 (HTML) |
| `title` | | 키와 다르게 보여 줄 이름 (예: `'? :'`, `'sigaction (sa)'`) |

**함수 (`kind:'func'`) — 고정 틀, 모든 칸 필수**

```js
gpiod_chip_open: { kind:'func', role:'init',
  sig:'struct gpiod_chip *gpiod_chip_open(const char *path);',
  summary:'① GPIO 칩 장치 파일을 열어 칩 객체를 만든다.',
  params:[  // [이름, 타입, 이 코드에서 넘긴 값, 설명]       없으면 []  → "파라미터 없음"
    ['path', 'const char *', '<code>CHIP_PATH</code> = <code>"/dev/gpiochip0"</code>', '열 장치 파일 경로'],
  ],
  paramNote:'(선택) 표 아래 한 줄',
  ret:[     // [값, 의미, 이 코드에서의 처리]                 void 도 한 줄로 적는다
    ['<code>NULL</code>', '실패, errno 에 이유', 'perror 출력 후 return EXIT_FAILURE'],
  ],
  retNote:'(선택)',
  how:'<p>동작 설명 (HTML). 레지스터 이야기는 넣지 않는다</p>',
  fails:[   // [원인, 증상 / errno, 이 코드에서 일어나는 일, 대처]
    ['권한 없음', '<code>Permission denied</code> (EACCES)', 'L31 에서 종료, 코드 1', 'gpio 그룹 추가'],
  ],
  failNote:'(선택) 노란 박스로 강조할 핵심 주의 한 줄',
  vars:[ ['chip','리턴값을 저장'], ['CHIP_PATH','파라미터로 넘김'] ],     // [심볼 키 또는 이름, 관계]
  funcs:[ ['gpiod_chip_close','짝: 칩 닫기'] ],                          // SYM 에 없는 이름은 회색, 클릭 안 됨
},
```

카드에 그려지는 순서: 배지 → 이름 → 원형 → 요약 → 등장 줄 → 📥 파라미터 → 📤 리턴값 → ⚙ 동작 → ⚠ 실패 원인 분석 → 🔗 관련 변수·상수 → 🔗 관련 함수.
`vars`·`funcs` 에 적은 심볼은 코드 화면에서도 노란 점선 테두리로 표시된다.

**변수 · 매크로 · 상수 · 키워드 · 연산자**

```js
offset: { kind:'var', role:'init', sig:'unsigned int offset = LED_LINE;',
  summary:'...',
  sections:[ ['제목', '<p>HTML</p>'], ['수명', '...'] ],   // 자유 섹션
  regs:['GPFSEL1'],          // (선택) 레지스터 비트 그림 — REGS 에 정의된 이름
  extra:'<h3>...</h3>...',   // (선택) 섹션 뒤에 붙는 HTML
  related:['LED_LINE','op_addr'],                            // 관련 심볼 버튼
},
```
> 변수·매크로·상수 카드의 틀은 아직 사용자가 정하지 않았다. 정해지면 함수처럼 고정 틀로 바꾸고 이 절을 고친다.

연산자는 키 `op_not`(`!`) · `op_ternary`(`?`) · `op_addr`(`&`) 로 정의하면 코드의 해당 기호가 클릭 가능한 요소가 된다. 정의하지 않으면 그냥 글자로 남는다.

### 3-4. ALIAS — 다른 이름을 같은 카드로

```js
const ALIAS = {
  gpiod_chip:'chip',          // 타입 이름 → 그 타입의 변수 카드 (타입 색으로 표시)
  sa:'sigaction',             // 구조체 변수 → 관련 함수 카드
  GPIOD_LINE_VALUE_INACTIVE:'GPIOD_LINE_VALUE_ACTIVE',   // 짝 상수 → 카드 하나로
  goto:'cleanup',
};
```

### 3-5. REGS — 레지스터 (선택)

레지스터를 다루는 파일(03_gpiomem, 04_speed 등)에서만 쓴다. 안 쓰면 `const REGS = {};`.
```js
const GPIO_PHYS = 0xFE200000, GPIO_BUS = 0x7E200000;
const REGS = {
  GPSET0: { off:0x1C, access:'W', title:'출력 Set 0 (GPIO 0~31)',
            hl:{ lo:17, hi:17, bits:'1', label:'비트 17 = 1 → GPIO17 High' }, zero:true },
};
```
레지스터 카드는 `SYM['REG_<이름>'] = { kind:'reg', role:'global', title:'<이름>', sig:'주소', summary:'...', regs:['<이름>'], extra:'설명 HTML', related:[...] }` 형식으로 추가한다.
변수·매크로 카드에서 `regs:['<이름>']` 을 주면 같은 비트 그림이 카드 안에 그려진다. (함수 카드에는 넣지 않는다)

## 4. 내용 작성 기준

### 화면 규칙 (사용자 지정)
- **개요에는 함수·변수·흐름만 넣는다**: 요약, (선택) 시뮬레이션, 실행 흐름, 보는 법. 하드웨어 계층도, 객체 수명 표, 레지스터 바로가기는 넣지 않는다.
- **코드 뷰어의 주석**: 파일 머리 주석(첫 `#include` 위)만 보이고 나머지는 엔진이 자동으로 지운다. 데이터에서 따로 할 일은 없다.
- **함수 카드에 레지스터 정보를 넣지 않는다**: 레지스터 그림, 비트 연산, 주소 모두 넣지 않는다.

### 문장
- 한국어, 짧은 평서문("~한다"). 용어는 처음 나올 때 풀어 쓴다.
- 일반론보다 **"이 코드에서"** 를 쓴다: 넘긴 실제 값, 실제 줄 번호(`L47`), 실제로 일어나는 일.
- 직접 확인하지 못한 동작(보드에서 실행하지 못한 것)은 추정이라고 밝힌다.

### 함수 카드 칸별 기준

| 칸 | 꼭 들어갈 것 |
|---|---|
| 파라미터 | 실제로 넘긴 값(변수 이름과 그 값), 허용 범위, NULL 이 될 수 있는지 |
| 리턴값 | 성공 값과 실패 값을 모두 적는다. 코드가 확인하지 않으면 **"확인하지 않는다"** 를 굵게 |
| 동작 | 3~5줄. 표를 쓰면 호출 위치별 차이(예: L54 vs L60)를 보여 준다 |
| 실패 원인 | 원인마다 한 줄: 터미널에 보이는 **실제 메시지**(`Device or resource busy`)와 errno, 이 코드의 흐름(어느 줄로 가는지, 종료 코드), 사용자가 할 수 있는 **구체적 대처**(명령어 포함). "해당 없음"인 원인도 학습용으로 남긴다 |
| 관련 변수·함수 | 이름만 적지 말고 **관계를 한 줄로**: "리턴값을 저장", "짝: 해제", "다음 단계" |

### 놓치기 쉬운 것 체크
- [ ] 코드에 나오는 함수 호출에 모두 카드가 있는가 (build.sh 의 `△` 경고)
- [ ] 생성(`*_new`, `open`)과 해제(`*_free`, `close`, `release`)를 서로 `funcs` 에 "짝" 으로 연결했는가
- [ ] 리턴값을 무시하는 호출을 실패 원인 표에 반영했는가 (Segmentation fault / 조용한 실패)
- [ ] SECTIONS 가 코드의 모든 실행 줄을 덮는가 (색 띠가 빠진 줄이 없는가)
- [ ] 카드 안 줄 번호 링크(`data-line`)가 원본 줄 번호와 맞는가

## 5. 자주 하는 실수

| 실수 | 결과 | 예방 |
|---|---|---|
| 소스를 데이터나 템플릿에 손으로 옮겨 적음 | 원본과 달라짐 | 소스는 항상 build.sh 가 넣는다 |
| `result/*.html` 을 직접 수정 | 다음 빌드에서 사라짐 | 데이터나 템플릿을 고친다 |
| 데이터 JS 의 따옴표·백틱 짝 실수 | 화면이 통째로 안 나옴 | build.sh 의 `✗ 스크립트 오류` 메시지 확인 |
| 문자열 안에 `\n` 을 그대로 씀 | 실제 줄바꿈이 됨 | 화면에 `\n` 을 보여 주려면 `\\n` |
| 템플릿을 고치고 한 파일만 빌드 | 결과물끼리 모양이 다름 | `for f in tools/data/*.js; do ...` 로 전부 다시 빌드 (아래) |

```bash
# 모든 결과물 다시 빌드 (데이터 이름 → 원본 파일 이름: _h 로 끝나면 .h, 아니면 .c)
for d in tools/data/*.js; do n=$(basename "$d" .js); f="$n.c"; [[ $n == *_h ]] && f="${n%_h}.h"; bash tools/build.sh "$f"; done
```

## 6. 다른 폴더로 배포할 때

| 복사할 것 | 비고 |
|---|---|
| `CLAUDE.md` | 그대로 |
| `tools/작성방침.md`, `tools/viewer_template.html`, `tools/build.sh` | 그대로 |
| `tools/example/example.c`, `tools/data/example.js` | 기준 예시 |
| 빈 `upload/` 폴더 | 분석할 코드를 넣을 곳 |

**복사하지 않는 것**: `tools/data/` 의 실제 분석 대상 데이터(예시 외), `result/`, 기존 `upload/` 내용.

받은 쪽에서 `bash tools/build.sh tools/example/example.c` 를 실행해 `result/example.html` 이 열리면 준비가 끝난 것이다.
필요한 환경: bash(Windows 는 Git Bash), Chrome 또는 Edge(실행 검증용, 없으면 검증만 건너뜀), 결과물을 열 때 인터넷(Tailwind CDN).
